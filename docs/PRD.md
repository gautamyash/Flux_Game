# FLUX — Product Requirements & Engine Spec (v1)

Source of truth for visuals: `/design` (Claude Design export). Source of truth for rules: this file + `app/src/engine`.

## 1. Product
FLUX is an offline, single-player path puzzle for Android (iOS-compatible). The player draws ONE continuous path through a square grid, connecting numbered nodes 1 → N in order, while special cells change the rules. Tagline: *Connect. Adapt. Solve.* No account, no backend in v1. Progress saves on device.

## 2. Core rules (authoritative)
- Grid is `n × n`, n = 4..10. Moves are orthogonal, one cell per move.
- The path starts on node 1. **Each cell can be used once** (no revisits). Dragging back onto the previous cell undoes one step.
- Nodes must be reached in order. Entering node k+2 or higher is invalid ("Not yet. Reach 3 before 4.").
- **Goal:** reach the last node. Covering every cell is NOT required. Bonus cells are optional.
- **Move budget:** each level has `maxMoves`. A move = one step into an adjacent cell. Teleport exit is free. Burn cells cost 2 moves total (1 step + 1 heat). Running out of moves before the last node fails the level.
- **Optimal moves** = solver result (fewest moves, ignoring bonuses). Stars: 3 = optimal, 2 = optimal+1..+2, 1 = anything solved. A collected bonus adds a bonus mark (shown separately; max 1 per level in v1).
- **Trapped:** if the head has no legal move and the level is unsolved, the level fails ("No valid move left"). Undo is always free and unlimited.

## 3. Special cells
| Cell | Rule | Feedback on violation |
|---|---|---|
| Dead `#` | Cannot enter. | "That is a wall. Go around it." |
| Direction `^ > v <` | After entering from any side, the next move MUST exit in the arrow direction. | "Wrong direction. Exit must be →" |
| Burn `B` | Crossable once. After the head leaves it, it is burned (blocked). Costs 2 moves. Burned cells stay blocked for the rest of the run.

**Fill rule:** every open cell (everything except walls and bonus stars) must be visited, and the final number is the finish: it cannot be entered until all other open cells are filled. | "That cell has burned out." |
| Teleport `T1..T3` | Pairs. Entering one moves the head to its partner (free). Partner cell is used. Next step leaves from the partner. | — |
| Freeze `F` | When crossed, the 8 neighbours lock for 3 moves (locked cells cannot be entered). Counter ticks down each move. | "Frozen for 2 more moves." |
| Switch `S` | When crossed, flips every gate in the level (closed ↔ open). Gates `G` start closed, `g` start open. | "That gate is closed." |
| Bonus `*` | Optional. Collect by crossing. | — |
| Countdown `c1..c5` | Value ticks down by 1 after EVERY move. If it reaches 0 before the head has entered it, the level fails. Entering it with value ≥ 1 is safe. At 0 it is an expired wall. | "The countdown cell ran out." |

Order of resolution for one move: validate (bounds, dead, used, burned, locked, closed gate, node order, direction exit) → move → apply cell effect (burn cost, teleport, freeze, switch, bonus, node reached) → tick locks → tick countdowns → check win / out of moves / countdown expiry / trapped.

## 4. Level format
ASCII rows, tokens separated by spaces, e.g.
```
. 1 > . .
. . . B .
2 . # . 3
```
Tokens: `.` empty · `#` dead · `1..99` node · `^ > v <` direction · `B` burn · `T1 T2 T3` teleport · `F` freeze · `S` switch · `G` closed gate · `g` open gate · `*` bonus · `c1..c5` countdown.
`LevelDef = { id, chapter, index, size, rows: string[], maxMoves, optimal, title? }`. All shipped levels are generated by `scripts/generate-levels.ts` and verified solvable by the solver; `optimal` is stored.

## 5. Progression (100 levels shipped, chapters 1–7 have 12 levels, chapter 8 has 16)
1 Basics · 2 Direction · 3 Hazards (burn, dead) · 4 Warp (teleport) · 5 Freeze · 6 Switch · 7 Pressure (countdown) · 8 Master (mixed). Level n+1 unlocks when n is solved. Each chapter's first level shows the "new mechanic" intro card. Special challenge levels: last level of each chapter (diamond node).

## 6. Modes
Classic (shipped), Daily (seeded from date, offline), Rush (timer + tight move limit; v1 = Classic levels with timer bar), Chaos, Master, Endless (procedural via generator + solver; v1 = enabled for sizes 5–7, generator runs on device). Chaos/Master may be marked "Coming soon" in UI if not finished.

## 7. Screens (all per `/design`)
Splash · Onboarding · Home · Chapters · Level map · Game · Pause · Level Complete · Level Failed · Daily · Modes · How to Play · Special-cell tutorial · Stats · Achievements · Settings · Themes (Paper, Graphite, Aurora, Ink, Sand + High contrast). Light/dark follow system or user setting.

## 8. Architecture
- Expo SDK 57, React Native 0.86, TypeScript strict, Reanimated 4, Gesture Handler, react-native-svg (board + glyphs on a 100×100 viewBox), expo-haptics, AsyncStorage.
- `src/engine` — pure TypeScript, zero React. `parseLevel`, `createState`, `tryMove`, `undo`, `legalMoves`, `solve`, `generate`. Fully unit-tested (Jest).
- `src/theme` — tokens (light/dark/skins) copied from the design tokens.
- `src/components` — `Board`, `Cell glyphs`, `PathLayer`, UI kit (Button, IconButton, TopBar, Modal, Toast...).
- `src/screens` — one file per screen. Custom lightweight stack navigator (`src/nav`).
- `src/store` — progress, settings, stats, achievements; persisted in AsyncStorage.
- `src/levels` — generated `levels.json` + chapter metadata.

## 9. Board sizing
`cell = floor(min(availW, availH, 760) / n)`; board side = `cell * n`. If `cell < 40`, wrap board in pan/zoom. Path width `0.34 × cell`, head ring `0.38 × cell`, node radius `0.33 × cell`.

## 10. Input
Pan gesture over the board. Cell = `floor((x − pad)/cell)`. Enter a neighbouring cell once the finger is 35% past the shared edge. Dragging onto the previous cell retracts one step. Lifting the finger keeps the path; tapping the head or a committed cell resumes/truncates there. Invalid moves: shake ±7px / 260ms, red tile tint, feedback line text, error haptic.

## 11. Accessibility
Every special cell has a unique shape + pattern. Reduced-motion switches animations to fades. High-contrast skin. 48dp touch targets. Cells expose accessibility labels ("Row 3, column 2, number 4, next target").

## 12. Release checklist (Play Store)
`eas build -p android --profile production` (AAB), adaptive icon, privacy policy URL, Data Safety (no data collected), content rating, target API per current Play policy, screenshots from the design sheets.
