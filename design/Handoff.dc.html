Board implementation notes

  • Layers, back to front: plate, tiles, path (Skia Path, stroke width 0.34 × cell), cells and glyphs, head cursor. Cells never re-render when the path grows; only the path layer does.
  • Path geometry: sample cell centres; for each interior point draw L to the previous edge midpoint, then a quadratic with the centre as control to the next edge midpoint. That is the half-cell smooth corner in every frame here.
  • Progress ramp: one linear gradient from the first cell centre to the head, stops path-active to path-ramp-end. Re-fit on every extend. Solved board swaps to path-completed.
  • Hit testing: compute cell from touch with floor((x − pad) / cell), enter on 35% overlap past the shared edge, resolve diagonals to the dominant axis. Gesture Handler Pan on the board root, runOnJS only when the cell changes.
  • Glyph states: each special cell is a pure function of (kind, state, pair, flags); animate by interpolating opacity, dash offset and scale on shared values so state changes cross-fade.
  • Teleport bridge: dashed quadratic between segment end and next segment start, control point offset 0.3 × distance perpendicular.
  • Theme: a single ThemeContext exposing the token names. Board skins override surface, raised, plate, grid, accent, ramp, special tints. High contrast is a skin.
  • Accessibility: expose cells as an accessibility grid, accessibilityLabel from the label table, accessibilityActions for extending the path, live region for announcements, AccessibilityInfo.isReduceMotionEnabled to switch every animation to its twin.
  • Sizing: compute boardSide and cellSize exactly as on the responsive artboard; below 40dp wrap the board in a pan and pinch container.
